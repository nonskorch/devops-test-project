# Решение

Разработчик просил развернуть код на нескольких машинах. Первый шаг к этому — упаковать приложение в образ, чтобы оно одинаково запускалось везде.

## Что добавил в репозиторий

- `Dockerfile` — сборка образа на базе Node 24
- `docker-compose.yml` — запуск сервиса и Nginx в отдельных контейнерах
- `nginx/default.conf` — конфиг Nginx, принимает запросы и передаёт их в сервис
- `.dockerignore` — чтобы лишние файлы не попадали в образ

## Требования

На машине должны быть установлены Docker и Docker Compose v2.

## Запуск

`docker compose up -d --build`

Команда собирает образ приложения и поднимает два контейнера: сервис и Nginx.

## Проверка

`curl http://localhost:8080/api/test` — возвращает `{"message":"Тестовое сообщение"}`

`curl http://localhost:3000/api/test` — соединение не устанавливается, сервис наружу не публикуется.

Swagger — `http://localhost:8080/api`, в заголовке страницы «Successful task».

Остановить — `docker compose down`

## Что делал

Сначала разобрался, что за приложение. Посмотрел `package.json` и `src/main.ts`. Приложение на NestJS, слушает порт 3000, все адреса с префиксом `/api`. Заодно увидел, что имя сервиса в Swagger берётся из переменной `SERVICE_NAME` — значит менять код не придётся.

Написал `Dockerfile`. Образ на `node:24-alpine` — облегчённый вариант, меньше размер и меньше лишних пакетов внутри. 
`package.json` копирую отдельно от кода: Docker кэширует слои, и при правке кода зависимости не переустанавливаются заново.

Настроил Nginx. Он слушает 80 внутри контейнера и передаёт запросы в `http://app:3000`. `app` — это имя сервиса из compose: Docker поднимает для контейнеров внутреннюю сеть со своим DNS, и внутри неё сервисы находят друг друга по именам. Удобнее IP-адресов, которые меняются при перезапуске.

Собрал `docker-compose.yml` с двумя контейнерами. У Nginx порт 8080 наружу, у приложения секции `ports` нет вообще — по заданию сервис не должен публиковаться. Имя для Swagger передаю переменной `SERVICE_NAME`, код приложения не трогал.

Проверил: через 8080 порт сервис отвечает, напрямую на 3000 порт — соединения нет, в Swagger заголовок «Successful task».

## Что можно улучшить

Добавить логи и мониторинг,централизованный сбор в логов в ELK и мониторинг состояния контейнеров в zabbix

Запуск не от root, cейчас процесс внутри контейнера работает от root, стоит переключить на пользователя `node` — он уже есть в официальном образе

HTTPS, Nginx сейчас принимает только HTTP ,для реального использования нужен сертификат и редирект с HTTP на HTTPS

В задании написано про развёртывание на нескольких машинах, а сейчас образ собирается и запускается локально на одной. Правильнее собрать образ один раз, положить в общее хранилище образов и разворачивать оттуда на всех машинах — тогда везде работает одна и та же версия

# Задание

К вам пришел разработчик и принес этот репозиторий со словами, что ему нужно развернуть этот код на нескольких машинах.

Он ожидает от вас, что вы добавите в этот репозиторий `Dockerfile` для сборки образа на основе Node24 и добавите Docker-compose файл, который запустит сборку, а потом поднимет данный сервис вместе с Nginx в отдельных контейнерах.

Сборка по его словам осуществляется командой `npm run build`, а запуск собранного кода командой `npm start`.

Nginx должен принимать запросы по порту `8080` и вести их в собранный сервис. Сам сервис не должен публиковаться наружу, предоставляя доступ только через Nginx.

Бонусом будет, если вы сможете поменять имя сервиса на "Successful task" в Swagger.

Чтобы проверить успешность развертывания достаточно выполнить запрос `/api/test`, который должен вернуть вам сообщение об успехе.

Для выполнения задания склонируйте себе репозиторий, внесите свои правки, залейте в удобный для вас публичный репо (Github, Gitlab, etc) и пришлите ссылку на него в личные сообщения.

Свои решения требуется прокомментировать, а также перечислить возможные способы улучшения данного репозитория с точки зрения DevOps.
